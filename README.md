# Решение TechArena

Оптимизация зон технического обслуживания: нужно открыть офисы, закрепить за ними объекты инфраструктуры и распределить специалистов. Максимизируется прибыль от обслуживания за вычетом транспортных расходов, стоимости офисов и штрафа за разброс нагрузки.

Строгие ограничения: ёмкость офисов, баланс числа объектов, покрытие необходимых навыков, уникальность назначений и геометрическая совместимость выпуклых зон с учётом расположения офисов. Расстояния берутся из входной матрицы, а нагрузка измеряется числом работ, включая повторы.

Решение — самодостаточный C++20-поиск с несколькими стартовыми разбиениями, локальными улучшениями и динамическим программированием для балансировки. [Инженерные выводы и обоснование решений](DESIGN.md), [измерения и исправление превышения времени](RESULTS.md).

Для отправки с компилятором **GCC C++ 14.2 (C++20)** загрузите один файл `main.cpp`.
Для компилятора **Docker (zip with Makefile)** загрузите `submission.zip`: в корне архива находятся `main.cpp` и `Makefile`.

Программа без аргументов читает `instance.json` из текущей папки и пишет туда `solution.json`. Внешние библиотеки, сеть, файлы предыдущих запусков и предварительно вычисленные ответы не используются. Общий бюджет — 270 секунд с начала `main`, включая чтение и разбор JSON, с запасом 30 секунд относительно лимита 300 секунд. Дедлайн проверяется внутри геометрии, ДП и подбора работников. Промежуточный допустимый ответ записывается сразу и обновляется при улучшении.

## Сборка и локальная проверка

```sh
g++ -O3 -DNDEBUG -std=c++20 main.cpp -o solver
# Или:
make build

# Короткий локальный прогон:
./solver instance0/instance.json results/check0.json 10

# Зависимости нужны только Python-валидатору:
python3 -m pip install -r requirements-dev.txt
python3 validate_solution.py instance0/instance.json results/check0.json

# Все пять открытых тестов:
python3 benchmark.py --seconds 270 --jobs 1
```

Для локальных экспериментов поддерживаются аргументы `INPUT OUTPUT SECONDS SEED`. В тестирующей системе аргументы не нужны. `make --silent run` запускает программу с фиксированными именами файлов.

## Алгоритм

Решение использует портфель эвристик:

1. Строит оптимальное решение с одним офисом как начальную нижнюю границу: объединение всех доступных навыков и наиболее прибыльные объекты в пределах ёмкости.
2. Генерирует разбиения плоскости на выпуклые области с разными наборами офисов, метриками и весами.
3. Назначает объекты по фактической матрице расстояний и проверяет возможность распределить специалистов. Для работников с одним навыком проверяются доступные количества; для нескольких навыков используется ограниченный поиск покрытия.
4. Улучшает назначения перестановками, заменами, переносами, открытием и сменой офисов, частичным разрушением зон и повторным заполнением. Хранит несколько вариантов с разными наборами офисов.
5. Динамическим программированием выбирает подмножества объектов в зонах и подходящий интервал нагрузки. Согласованные изменения нескольких офисов позволяют улучшать решения при большом штрафе за дисбаланс.
6. Проверяет геометрию по выпуклым оболочкам, включающим офисы. Битовые маски учитывают все объекты и все позиции офисов — как в официальном валидаторе. В части поисковых фаз временные конфликты разрешаются со штрафом; в файл попадают только допустимые ответы.

Повторяющиеся работы учитываются в нагрузке по отдельности, а для покрытия навыков достаточно одного подходящего специалиста в офисе. Количество объектов и количество работ балансируются раздельно.

Для более чем 64 различных навыков предусмотрено допустимое решение с одним офисом без ограничения на количество навыков. На предоставленных тестах этот запасной вариант не используется.

## Проверка и качество

Итоги полного прогона и ограничения сравнения с рейтингом приведены в `RESULTS.md`. Ответы лежат в `instance0/solution.json` … `instance4/solution.json`.

Дополнительно `work/stress_test.py` проверяет 67 случайных и граничных наборов официальным валидатором: точки на одной прямой, совпадающие координаты, строгий баланс, пустые входные множества, нулевую ёмкость и разные наборы навыков. Выполнены проверки AddressSanitizer и UndefinedBehaviorSanitizer.

`work/upper_bound.py` — отдельный инструмент для оценки верхней границы без геометрических ограничений; требует SciPy и не входит в посылку. Ответы и данные открытых тестов также не входят в посылку.

## Версия 2

Исправлены контроль глобального времени и выбор допустимого состояния при нарушенном балансе числа объектов. Добавлены совместное ДП по числу объектов и работ, более быстрый поиск интервала нагрузки, инкрементальное обновление оболочек, ближайшие соседи для направленных замен, перестройка пары зон и выбор числа офисов с учётом ёмкости. JSON-дерево освобождается перед поиском. Если верхняя граница доказывает оптимальность одного офиса, программа завершает работу сразу.

Для новой отправки используйте `main.cpp` либо `submission-v2.zip` (он идентичен обновлённому `submission.zip`). Старый архив сохранён как `work/submission-v1.zip`.
