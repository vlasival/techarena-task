# Версия 2: время выполнения и качество поиска

Посылки: `main.cpp` для GCC C++20 либо `submission-v2.zip` для Docker. `submission.zip` также обновлён до версии 2. Архив содержит только исходник и Makefile; тестовые данные и готовые ответы в него не входят. Старый архив сохранён в `work/submission-v1.zip`.

## Причина D и исправление

По сообщению системы, тест #1 не уложился в глобальное время. В программе нет потоков, мьютексов или ожидания stdin. Обнаружены три риска превышения времени:

- Таймер начинался после чтения и разбора JSON, хотя лимит тестера относится ко всему процессу.
- Перебор интервалов нагрузки имел квадратичную сложность по максимальному числу работ и редко проверял время; поиск распределения работников ограничивался узлами, но не временем внутри узла.
- После истечения бюджета могли выполняться построение геометрии, ДП и другие завершающие операции.

Теперь общий бюджет составляет **270 секунд с начала main**, включая чтение и разбор. Проверяется и прошедшее время, и CPU-время. Дедлайн проверяется внутри дорогих операций. При его достижении поиск прерывается исключением, текущий недостроенный вариант отбрасывается, уже записанный допустимый ответ сохраняется, процесс возвращает код 0. Оставлен запас 30 секунд до заявленного лимита 300 секунд. Разобранное JSON-дерево освобождается перед поиском.

## Улучшения алгоритма

- Инкрементальное построение оболочек: при сохранении старых вершин пересчитывается оболочка из старых вершин и добавленных точек. Для разнесённых ограничивающих прямоугольников проверка конфликта заканчивается сразу.
- Повторный подбор работников пропускается, если наборы требуемых навыков в изменённых офисах остались прежними.
- Вместо квадратичного перебора больших таблиц нагрузок используется проход с монотонными стеками и деревом диапазонов: основной перебор занимает порядка `M × L × log L`.
- Добавлено ДП одновременно по числу объектов и числу работ. Для фиксированного набора зон оно ищет подмножества с общим уровнем нагрузки и допустимым разбросом числа объектов.
- Исправлена ошибка сравнения: допустимый ответ больше не отбрасывается из-за более высокой сырой прибыли состояния, нарушающего жёсткий баланс.
- Добавлены ближайшие соседи, направленные замены, перестройка пары зон и выбор числа стартовых офисов с учётом ёмкостей.
- Если верхняя граница доказывает оптимальность решения с одним офисом, поиск заканчивается сразу. На instance2 это сокращает время с 285 секунд до миллисекунд с сохранением доказанного оптимума.

## Доказанный оптимум instance2

Доступные работники покрывают только навыки 0 и 2. Поэтому обслуживать можно 53 из 100 объектов.

Для фиксированного единственного офиса задача решается точно: берутся положительные значения `reward − distance` среди покрываемых объектов, сортируются и обрезаются по ёмкости. Штраф за дисбаланс при одном офисе равен нулю. Лучшие значения для офисов 0, 1, 2 соответственно:

| Офис | Лучшее значение |
|---|---:|
| 0 | 5.626351596202067 |
| 1 | 3.518240080822498 |
| 2 | −4.739821416640943 |

Для любого набора из нескольких офисов можно получить завышенную оценку: разрешить обслужить все 53 объекта без ограничений ёмкости, геометрии и распределения работников, назначая каждый объект в самый выгодный открытый офис. После вычета стоимости открытия верхние границы получаются такими:

| Открытые офисы | Верхняя граница |
|---|---:|
| 0, 1 | −7.149673652894272 |
| 0, 2 | −2.363334233178691 |
| 1, 2 | −4.645561418056801 |
| 0, 1, 2 | −31.830655974362145 |

Все эти границы отрицательны; пустое решение имеет значение 0. Следовательно, найденное решение с офисом 0 и значением **5.626351596202067 является глобальным оптимумом** этого теста. Независимая смешанная целочисленная модель без геометрии подтвердила ту же верхнюю границу.

## Дополнительные проверки

- 67 случайных и граничных тестов приняты предоставленным `validate_solution.py`.
- 80 независимых сравнений быстрого поиска интервала с исчерпывающим перебором дали одинаковые результаты.
- Регрессионный пример жёсткого баланса: совместное ДП нашло оценку 298 с 20 объектами и 30 работами в каждом офисе; официальный валидатор подтвердил результат.
- Проверки коротких дедлайнов на входах до 5 000 объектов и 30 офисов: процесс завершался примерно за бюджет плюс 4–8 мс с кодом 0 и допустимым ответом. Исходные измерения — `work/deadline/results.json`.
- Проверены работники с несколькими навыками, отсутствующие навыки, повторяющиеся работы, строгий баланс, совпадающие координаты, коллинеарные точки, пустые множества, нулевая ёмкость, более 64 навыков.
- AddressSanitizer и UndefinedBehaviorSanitizer: ошибок на пяти открытых тестах и дополнительном тесте с 64 навыками не обнаружено; их ответы также приняты валидатором.
- Сборка C++20 с `-Wall -Wextra -Wpedantic` прошла без предупреждений.
- Воспроизведена отдельная сборка и запуск из `submission-v2.zip`.
