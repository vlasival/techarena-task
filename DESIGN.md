# Инженерные выводы

## Постановка и выбор метода

Целевая функция:

`сумма reward − сумма distance − стоимость открытых офисов − alpha × (max задач − min задач)`.

Здесь одновременно выбираются офисы, объекты, специалисты и геометрические зоны. Ограничения связывают эти решения, поэтому реализован портфель эвристик с точными подзадачами, а не один жадный проход. Базовый вариант с одним офисом даёт допустимый ответ сразу; затем программа сохраняет только улучшения, прошедшие проверки.

## Два разных вида баланса

Число объектов — жёсткое ограничение, число работ — штраф в целевой функции. Эти величины нельзя подменять друг другом. Повторяющиеся работы увеличивают нагрузку, но не требуют отдельных работников одного и того же навыка.

При большом alpha одиночное добавление может ухудшать результат даже тогда, когда согласованное добавление во все офисы выгодно. Поэтому поиск включает изменения нескольких зон и ДП для выбора общего уровня нагрузки. Совместное ДП по количеству объектов и работ помогает находить решения, которые одномерное ДП пропускало из-за жёсткого баланса.

При исправлении второй версии обнаружена отдельная ошибка сравнения: сырая прибыль недопустимого состояния использовалась как порог для допустимых вариантов. После исправления допустимый результат оценивается с учётом того, что исходное состояние нарушает ограничения.

## Специалисты — ресурс между офисами

Специалист покрывает свой навык для всех объектов своего офиса, но не может быть назначен в несколько офисов. Поэтому важно не количество работ определённого типа, а число офисов, которым нужен этот навык.

Для работников с одним навыком достаточно проверять доступные количества. Для работников с несколькими навыками используется ограниченный поиск покрытия. Если наборы нужных навыков после изменения не поменялись, повторный подбор работников не нужен.

## Геометрия и стоимость перемещений

Выпуклая оболочка зоны включает офис. Проверка соответствует предоставленному валидатору: оболочки не должны иметь общего свидетеля среди всех объектов и позиций офисов, включая закрытые. Это отличается от полного запрета пересечения площадей многоугольников.

Расстояния из матрицы могут не совпадать с евклидовыми. Поэтому координаты используются для геометрии и направлений поиска, а прибыль считается по матрице. Поиск сочетает стартовые выпуклые разбиения, пространственных соседей и кандидатов, выгодных по фактическим расстояниям.

При сохранении старых вершин достаточно строить новую оболочку из них и добавленных точек. Битовые маски полуплоскостей ускоряют проверку свидетелей; ограничивающие прямоугольники позволяют быстро исключать заведомо разнесённые зоны. Пограничные вычисления используют консервативный допуск, поскольку первоначальная проверка без него давала ошибки из-за округления.

## Надёжность времени выполнения

Внешний протокол v1 сообщил о превышении глобального времени на тесте #1. Проверка таймера только во внешнем цикле недостаточна: чтение JSON, ДП или поиск работников могут занять заметное время внутри одной итерации.

Версия 2 считает бюджет с начала main, проверяет дедлайн внутри дорогих операций и оставляет 30 секунд запаса до заявленного лимита. При остановке сохраняется последний записанный допустимый ответ. Большое синтаксическое дерево JSON освобождается перед поиском. Если верхняя граница доказывает оптимальность одного офиса, дальнейший поиск прекращается.

## Что подтверждено, а что остаётся эвристикой

Глобальная оптимальность доказана для открытого instance2. Быстрый подбор интервала нагрузки проверен на 80 независимых сравнениях с исчерпывающим перебором; совместное ДП имеет отдельный регрессионный пример. Допустимость проверялась официальным валидатором, случайными тестами и санитайзерами.

Для остальных инстансов оптимальность не доказана. В сравнении v1/v2 два открытых результата выросли, два сохранились, один снизился. Охлаждение зависит от прошедшего времени, поэтому результат зависит от скорости процессора и нагрузки системы. Закрытые входные данные отсутствуют; итоговый рейтинг новой версии можно установить только повторной отправкой. Полные числа и ограничения сравнения приведены в [RESULTS.md](RESULTS.md).
