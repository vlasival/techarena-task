# Проверка решения

Посылки: `main.cpp` для GCC C++20 либо `submission.zip` для Docker. Архив содержит только исходник и Makefile; тестовые данные и готовые ответы в него не входят. Архив отдельно распакован, собран и запущен.

## Открытые тесты

Финальный прогон выполнен без аргументов в папке каждого теста, то есть проверяет именно контракт `instance.json` → `solution.json`. Бюджет — 285 секунд на тест. Все значения ниже — сырые значения целевой функции, а не сумма нормированных баллов рейтинга.

| instance1 | 17.39147155 | **32.22995749** | 85.32% | 2 / 46 | OK |
| instance2 | 5.62635160 | **5.62635160** | 0.00% | 1 / 29 | OK |

| instance4 | 8516.30807976 | **18892.09615226** | 121.83% | 4 / 160 | OK |

Каждый из пяти процессов завершился самостоятельно примерно за 285 секунд с кодом 0. После завершения все ответы повторно проверены официальным валидатором. Полные числа сохранены в `results/final_scores.csv`. Локальная сборка: Apple Clang 21, C++20, macOS arm64; GCC 14.2 и среда NSUTS здесь не установлены.

Время и результат эвристического поиска немного зависят от скорости процессора и нагрузки системы: охлаждение задаётся по фактически прошедшему времени. Начальное значение генератора случайных чисел фиксировано.

## Доказанный оптимум instance2

Доступные работники покрывают только навыки 0 и 2. Поэтому обслуживать можно 53 из 100 объектов.

Для фиксированного единственного офиса задача решается точно: берутся положительные значения `reward − distance` среди покрываемых объектов, сортируются и обрезаются по ёмкости. Штраф за дисбаланс при одном офисе равен нулю. Лучшие значения для офисов 0, 1, 2 соответственно:

| Офис | Лучшее значение |
|---|---:|
| 0 | 5.626351596202067 |
| 1 | 3.518240080822498 |
| 2 | −4.739821416640943 |

Для любого набора из нескольких офисов можно получить завышенную оценку: разрешить обслужить все 53 объекта без ограничений ёмкости, геометрии и распределения работников, назначая каждый объект в самый выгодный открытый офис. После вычета стоимости открытия верхние границы получаются такими:

| Открытые офисы | Верхняя граница |
|---|---:|
| 0, 1 | −7.149673652894272 |
| 0, 2 | −2.363334233178691 |
| 1, 2 | −4.645561418056801 |
| 0, 1, 2 | −31.830655974362145 |

Все эти границы отрицательны; пустое решение имеет значение 0. Следовательно, найденное решение с офисом 0 и значением **5.626351596202067 является глобальным оптимумом** этого теста. Независимая смешанная целочисленная модель без геометрии подтвердила ту же верхнюю границу.

## Дополнительные проверки

- 67 случайных и граничных тестов приняты предоставленным `validate_solution.py`.
- Проверены работники с несколькими навыками, отсутствующие навыки, повторяющиеся работы, строгий баланс, совпадающие координаты, коллинеарные точки, пустые множества, нулевая ёмкость, более 64 навыков.
- AddressSanitizer и UndefinedBehaviorSanitizer: ошибок на пяти открытых тестах и дополнительном тесте с 64 навыками не обнаружено; их ответы также приняты валидатором.
- Сборка C++20 с `-Wall -Wextra -Wpedantic` прошла без предупреждений.
- Воспроизведена отдельная сборка и запуск из `submission.zip`.

## Сопоставление с рейтингом

На скриншоте рейтинг по 11 тестам; в предоставленной папке находятся 5 инстансов. Соответствие их номерам в рейтинге и остальные входные данные отсутствуют. Поэтому по локальному прогону нельзя достоверно вычислить сумму нормированных баллов или обещать место рядом с лидерами. Это нужно проверить отправкой посылки в систему соревнования.

На остальных тестах используется эвристика: доказательства глобальной оптимальности для них нет. Результаты предыдущих запусков не читаются программой и не используются для инициализации.
